# Security and stability review — 23 October 2026

## Scope and outcome

Reviewed the supplied Next.js App Router API adapter, all seven content controllers/models, admin authentication, upload storage and serving, API clients, routing, configuration, lockfile and relevant frontend flows. Applied backend security/reliability fixes and small functional corrections. No redesign, CSS/class changes, school-content rewrite, or media replacement was performed.

This review and its fixes apply to this archive. No live site, hosting account, production database or DNS configuration was accessed or modified. The original database is not included in the upload. A code audit cannot guarantee zero bugs, uninterrupted hosting or protection against every attack.

## Findings and changes

| Severity | Original issue and practical impact | Change |
| --- | --- | --- |
| Critical/High | Dependency audit reported critical/high advisories including the installed Next.js 15.5.25 and image-processing/dependency packages. Advisory applicability varies with usage. | Updated Next.js to 15.5.28, sharp and DOMPurify; patched compatible PostCSS, selector-parser, redirect and source-map dependencies. Removed unused Multer 1 and Express limiter dependencies. Production audit now reports zero known vulnerabilities; build-tool exceptions below. |
| High | `app/api/[...path]/route.js` parsed multipart requests and wrote uploads **before** `protect`. Anonymous requests could write files and consume disk/decoder resources even when rejected afterward. | Resolve route, reject untrusted origins, check authentication and upload rate limits before reading multipart data. Validate files before writing; clean up new files on validation/DB failures. |
| High | The existing CSRF middleware was never called by the Next.js adapter; production cookies used `SameSite=None`. | Require exact configured trusted origin for every write, reject cross-site fetch metadata, use same-site HttpOnly cookies and Secure in production. |
| High | Login/password endpoints had no functioning request limiter. Installing an Express limiter did not apply it to Next.js. | Atomic MongoDB counters shared across processes/restarts; client and account login limits; upload limits; trusted-proxy setting defaults off. |
| High | JWTs remained usable after password changes or logout. | Verify HS256 and a database session version. Password change, explicit seed reset and logout revoke earlier sessions. Legacy tokens without a version are rejected on rollout. |
| High | Upload `File` size checks occurred after the entire multipart request was buffered. Unchecked total bodies could exhaust memory. Images were written before content checks. | Streamed total-body limits with a body-read deadline, field/file count limits, sequential image processing, pixel/frame limits, decode and MIME checks, document signature checks. Ingress limits remain necessary. |
| High | Admin email/password were included in `.env` in the submitted archive; runtime DB connection automatically created an admin from them. | Removed `.env` from the corrected package and all runtime credential bootstrap code. Added interactive `seed:admin` and explicit `seed:admin:reset`, storing only bcrypt hashes in MongoDB. Kept the existing password-hashing algorithm/cost. Existing DB credentials still require a deliberate reset on deployment. |
| Medium | Express cookie `maxAge` milliseconds were forwarded unchanged into Next.js, which expects seconds. This gave the browser cookie an unintended approximately 1,000-fold lifetime, although JWT validation still limited token use to seven days. | Convert to seconds at the adapter boundary; regression asserts `Max-Age=604800`. |
| Medium | Several updates deleted old media before the database update succeeded. Validation or DB failure could break existing pages. Circular replacement/deletion also left obsolete PDFs behind. | Queue old-file deletion and execute it only after DB success; clean up newly written files on failed operations; enable update validators and handle concurrently missing records. Disk/DB crash consistency remains an operational limit. |
| Medium | Raw JSON objects were accepted for scalar fields, including login queries; malformed JSON/IDs could produce 500s and error messages exposed internals. | Reject nested/operator/array payloads, prototype-style field names, excessive field size/count and invalid IDs; use controlled 400/409 errors and generic server failures. |
| Medium | Public detail endpoints returned inactive records even though public list endpoints hid them. | Public detail queries require `isActive: true`. Admin `/all` endpoints remain authenticated and include inactive records for editing. Known media URLs remain public. |
| Medium | File endpoints loaded an entire document into memory for every request and lacked response safeguards. | Stream files with range and HEAD support, check real paths for symlink escape, set `nosniff` and a restrictive upload CSP, use attachment disposition for non-image/non-PDF documents. Both legacy URL prefixes remain supported. |
| Medium | Single-image compression used an empty disk path in the Next.js adapter and attempted JPEG output under non-JPEG names. | Process the supplied buffer, preserve the format and transparency, and keep animated images. Remove the unused legacy Multer path. |
| Medium | The public `/login` frontend accepted any nonempty email/password through placeholder authentication. It did not grant backend admin privileges but falsely reported successful login. | Keep its UI and connect it to the actual admin authentication endpoint. No student/parent accounts or new role system were invented. |
| Medium | MongoDB startup had no explicit connection-selection bounds; liveness depended on DB access. | Bounded connection/pool settings with retry after failure, independent liveness and a separate readiness endpoint. |
| Low/Functional | Inactive circulars disappeared from the admin listing; create handlers ignored the submitted active flag; one founder link pointed at an absent route. | Use authenticated `/circulars/all` in admin; honor active status on create; correct the founder URL. |
| Low | Debugging output included authentication responses and gallery form data; logout showed success even after server failure. | Remove routine debug payload logs and show a logout error when revocation failed. Server errors avoid returning internal details. |

Primary changed areas: `app/api/[...path]/route.js`, the two upload route files, `src/server/security/`, `src/server/middleware/`, `src/server/config/`, controllers/models, `scripts/seedAdmin.js`, dependency manifests and the small frontend corrections listed above. `src/data/seedData.js` remains the existing public site-content data; admin credentials live in neither that file nor any other source file.

## Verification results

- Production build: `npm run build` passed on Node.js 24.19.0 / Next.js 15.5.28.
- Security suite: **10 passed, 0 failed, 0 skipped**, with a temporary, isolated MongoDB 8.2.6 instance. The test database was destroyed afterward. No production credentials were used.
- Database suite exercised new/existing/reset seeding; bcrypt verification; successful and failed login; JWT signature enforcement; cookie expiry and flags; authenticated and unauthenticated requests; create/list/update/delete for management, committee, staff, teaching staff, gallery, circulars and downloads; inactive detail rejection; invalid upload rejection; preservation of old files and cleanup of new files on failed updates; shared limiter concurrency; 429 responses; password-change and logout revocation.
- Additional tests covered origin checks, operator/prototype/nested input rejection, malformed cookies, body limits, bcrypt byte limits, upload traversal, forged image MIME, PNG transparency, file ranges, HEAD and symlink containment.
- Production HTTP smoke test: **44 public/admin page routes returned 200**; **16 homepage assets loaded**. Liveness, unauthenticated check, invalid-record ID and an existing PDF URL returned their expected statuses. An HTTP 200 for an admin shell does not bypass API authentication; client-side interaction/visual regression is not exhaustively verified by these checks.
- `npm audit --omit=dev`: **0 known vulnerabilities** at verification time.
- Full `npm audit`: **5 high findings**, all in the Tailwind 3 build dependency chain (`braces`, `chokidar`, `micromatch`, `fast-glob`, `tailwindcss`). These are not five confirmed remotely exploitable routes. The root braces advisory has no patched version available in the installed dependency line; npm recommends Tailwind 4. No forced major CSS migration was performed because preserving the site's existing styling is an explicit requirement. Use trusted build inputs and keep the dev server private. Plan a separately tested Tailwind migration; repeat both audits before release.

The default `npm test` run skips the database suite without `TEST_MONGODB_URI`; the full result above was obtained with a disposable MongoDB instance supplied explicitly. Tests are included so this can be reproduced.

## Required deployment actions and remaining limits

1. Follow `README.md`: back up DB/uploads; configure the existing DB URI, fresh JWT secret and canonical origin; rotate the original MongoDB password; run the explicit admin password-reset seed for the existing email; build and deploy. Removing credentials from the new archive does not revoke secrets already present in an older upload, backup or repository history.
2. Keep MongoDB private with authentication/TLS where appropriate. The archive cannot establish whether the live DB is publicly reachable, which database roles exist, or how the host handles secrets.
3. Retain a durable shared upload volume, monitor disk/RAM, configure HTTPS/proxy rate and body limits, supervise the process, and test backups. This source fix cannot prevent downtime from exhausted hosting resources, DDoS, a DB outage, missing mounts or expired certificates.
4. File signatures do not replace antivirus/content-disarm scanning, especially for Office documents and archives. Uploads are restricted to authenticated admins, but trusted admins can still upload a harmful document. A storage quota and malware scanning can be added with a deliberate storage policy.
5. Old orphan files already on disk are not automatically deleted: the archive lacks production DB references needed to identify them safely. A process crash can also leave orphan files between filesystem and DB operations. Cleanup failures are logged. No existing media was purged from the package.
6. Staff fields such as DOB, qualification and appointment details remain in the existing public API schema; review whether publishing those fields fits your school's intended policy. No unsolicited redaction or requirement change was made.
7. Public lists are still returned in the existing format without pagination to preserve current UI behavior. Large future content volumes need pagination and performance/load testing. Browser flows, email delivery, infrastructure hardening, live deployment and exhaustive load testing were not performed.

Reference guidance consulted: Next.js security update of 14 October 2026 (`https://nextjs.org/blog/nextjs-security-update-october-14-2026`); OWASP Password Storage, Authentication and Session Management Cheat Sheets. The npm audit results describe the exact resolved lockfile at review time, not a permanent security guarantee.
